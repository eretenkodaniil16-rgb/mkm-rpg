# MKM RPG — отчёт направления «Визуал и структуры» для чата «главный»

Дата: 8 ноября 2026. Состояние: **DRAFT / интеграционное тестирование**, не готово к объединению с main.

## Ссылки и зависимости

- Репозиторий: `eretenkodaniil16-rgb/mkm-rpg`.
- Ветка: `feature/environment-vanillaplus-watchtower-v1`.
- Draft PR: https://github.com/eretenkodaniil16-rgb/mkm-rpg/pull/60
- Основа: `integration/world-e2-1-fabric-character-v4-qa` (PR #45, Fabric 26.3/CharacterData v4). Историческая `main` содержит NeoForge, мерджить в неё напрямую нельзя.

## Что реализовано

1. **Vanilla+ Dark Fantasy** — исходный style guide с палитрой, художественными правилами, материалами, масштабом Minecraft, разрешением текстур 16×16.
2. **Шесть оригинальных блоков:** `mkm:aged_ashlar`, `mkm:mossy_ashlar`, `mkm:cracked_ashlar`, `mkm:charred_timber`, `mkm:rusted_iron`, `mkm:rune_slate`. Для каждого существуют оригинальная PNG 16×16, blockstate, cube model, модель предмета, предметная регистрация и локализация.
3. **Башня с лагерем:** три файла NBT `mkm:ruined_watchtower_01/02/03` (23×14×19), разные разрушения, основной вход и соединённый с лагерем двухблочный мост, лестница, верхняя площадка, руны, лагерь, бочка с `mkm:chests/watchtower`. Предварительные площадки под обычных врагов: (7,5,9), (18,5,13), под элиту: (10,12,8). Записи сущностей в NBT отсутствуют.
4. **Рунический эффект:** клиентские частицы `END_ROD` через стандартный `animateTick`. Отключение `-Dmkm.runeParticles=false`, без глобальных шейдеров, обязательного Iris и вмешательства в Combat/Magic.
5. **Контролируемое размещение:** GM-команда `/mkmenv watchtower <1..3> <x> <y> <z>`. Сервер проверяет пустоту всего целевого объёма, наличие загруженных чанков, мировую границу и опоры с допустимым перепадом не более 4 блоков, затем размещает шаблон. Прямое перезаписывание уже занятых блоков этой командой запрещено. Дополнительный вариант без проверки `/place template` использовать рядом с постройками игроков **нельзя**.
6. **Контроль качества:** Python-валидатор PNG/CRC, палитры NBT, размера, моделей, локализации, таблицы добычи и отсутствия автоматической генерации; Java/JUnit тесты проверки участка; отдельный workflow Java 25/Fabric.

## Доказательства и ограничения

- На раннем коммите CI успешно выполнил проверку ресурсов, Java25 build/test, запуск выделенного сервера и Xvfb-клиента.
- На коммите с защищённой командой установки CI Environment (static+Java25 test/build) и основной Fabric CI (полный build и server/client smoke) также завершились успешно.
- **Не проверено в реальном игровом клиенте:** фактическая установка шаблона с командой, NPC-навигация, вид материалов, отсутствие пурпурных текстур, взаимодействие с бочкой, Iris/Sodium, FPS/MSPT, сохранение после рестарта, парное сетевое тестирование. Соответственно, не объявлять прототип «готовой игровой локацией» до ручной приёмки.
- Нет автоматической генерации, structure sets и biome filters. Защита от инцидентного перезаписывания при GM-команде не равна полноценной защите регионов/приватных построек, не обеспечивает атомарный откат после технического сбоя.
- Шаблон содержит одну бочку (блок-сущность) и ванильный костёр (возможна блок-сущность); сам рунический блок блок-сущность не использует. Реальное число BE, draw calls и GPU нагрузка не измерялись.

## Что требуется от остальных направлений

**World («мир»)** — утвердить биомы и исключения, частоту/расстояния, разрешение размещения с учётом чанков и сохранений, защиту пользовательских территорий, положение и жизненный цикл квестовых встреч. Только после этого обсуждать biome-driven worldgen. В рамках существующего распределения ответственности это задача World, а не визуальной команды.

**Враги и AI** — определить совместимые EntityType и поведение, безопасную активацию противников, навигацию по лестнице/проходам, серверную семантику элитного противника. Визуальная команда не создаёт второй AI/encounter runtime.

**QA / главный интегратор** — проверить PR #60 поверх PR #45, Java25 CI, запуск на выделенном сервере, ручное размещение на пустом участке и отклонение при блокировке; тестировать со старым миром только после резервной копии. Объединение в историческую main запрещено.

**Критерий готовности:** видимый в ванильном рендере качественный участок мира, корректная коллизия/лестница, реальный сундук с добычей, отсутствие конфликтов с World/AI и проверенные запреты на повреждение построек при разрешённом способе размещения. Пока этот критерий полностью не достигнут.
